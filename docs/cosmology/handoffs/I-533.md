## Why this exists, and why the earlier reason for deferring it was rejected

`repo_reshape.md` §7's M0 row has a **"Retire on completion"** column: the legacy code M0
deletes once it lands. For M0 that is the four CLI subcommands §5's capability ledger marks
`drop` — never carried into the new package — plus their tests. #524 deferred them with the
reason *"retiring `plot` would break every `examples/*/run.sh`"*.

**The user rejected that reason on 2026-09-09**, and rightly: it says we keep legacy code
because deleting it breaks callers of that same legacy code. The programme's whole point is
to retire legacy in favor of the ground-up rebuild. A `run.sh` whose only job is to drive a
dropped subcommand retires **with** it.

**The one legitimate brake is an interaction with parts not yet ported** — code we still need
working in order to build, run or test the new package. That is the distinction this session
must draw, carefully, with the import graph rather than by eye.

## What is being retired, and what replaces it

| subcommand | why it goes | what replaces it |
|---|---|---|
| `sweep` | thesis-era parameter campaigns; the new pipeline samples through Cobaya | Cobaya samplers |
| `sample` | legacy nested-sampling inference (D9) | Cobaya + its samplers; `tidal/inference/` retires at M1b |
| `analyze` | chain analysis and the t-independence audit, serving thesis-era campaign artifacts | GetDist / anesthetic post-processing |
| `plot` | visualization helpers for `tidal simulate` — solver snapshots with no cosmology counterpart | **GetDist** (Cobaya's standard companion, installed with it) for posteriors and triangle plots; **anesthetic** for nested-sampling output — the tool TorC itself used |
| `measure` | §5.3 records it dropped; §7's M5 row retires `tidal/measurement/` | re-implemented behind the new package's own gates where still wanted |

**`plot` retires *toward* GetDist and anesthetic — nothing is re-implemented** (§5.3). Our
extension's job is to *emit what those tools already read*: Cobaya-native chains
(`.txt` + `.paramnames`, automatic once we are a Cobaya `Theory`) and CAMB-convention spectra.
Say so in the commit message that removes it, so the intent is not mistaken for a capability
loss.

## Method

1. **Map the import graph first**, for `tidal/cli/{_sweep,_sample,_analyze,_plot,_plot_command,_campaign}.py`
   and the `measure` path. For each symbol imported from outside `tidal/cli/`, record: who
   imports it, whether that importer is itself retiring, and at which milestone.
2. **Delete** every drop-row subcommand, its module, its CLI registration and its tests where
   nothing *not-yet-ported and still needed* imports it.
3. **Where a library function is genuinely needed** by `tidal/measurement/` or
   `tidal/inference/` (both of which retire later — M5, M1b), **do not delete it and do not
   leave it in `tidal/cli/`**: move it to the library module that uses it, and record in the
   commit and in `repo_reshape.md` §5 the milestone that retires it. A CLI module surviving
   only because a library imports it is the dependency inversion that makes later retirement
   hard.
4. **`examples/**/run.sh` and legacy campaign scripts** that only drive dropped subcommands:
   delete them. The thesis-era code stays reachable at tag **`v0.53.0`** — cite that tag in
   the commit message and in the CHANGELOG entry so the provenance is not lost. Where a
   `run.sh` does something still meaningful (`derive`, `simulate`, `inspect`, `validate`),
   keep it and remove only the retired invocations.
5. **`docs/tex/`**: sections describing deleted capabilities are now wrong — remove them, or
   mark them "retired at `<sha>`". `CLAUDE.md`'s rule is that legacy docs are *not* stale
   until the capability is actually replaced; this is the moment they become stale.
   `docs/*.md` campaign records stay as **history** — do not rewrite them.
6. **Report, do not edit**, the lines needing change in `CLAUDE.md` (its "11 subcommands"
   list, the source→test mapping, and the `sweep`/`sample` command examples) and in
   `scripts/README.md`. Those files are being edited concurrently by I-REM; the orchestrator
   applies your list at merge.
7. **The frozen oracle must stay valid.** `tests_cosmo/data/oracles/` freezes `derive`,
   `inspect` and `validate` output — none of which you are touching — so
   `--check` must still report **185 fixtures current** when you are done. If it does not,
   stop: you have changed something the oracle covers.
